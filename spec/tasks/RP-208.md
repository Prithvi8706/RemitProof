## 1. Objective and rationale

Two tools for the human task H-203.

1. `blind`: writes one file per original case that contains the records and an empty label form, and nothing of the first label.
2. `agreement`: compares the first labels with the filled forms and reports Cohen's kappa on allocate against review, exact-allocation agreement, review-family agreement, and the list of cases that need adjudication.

Why: the benchmark's labels are its ground truth. A label one person wrote and nobody checked is an opinion. This task was not in the first inventory. It was added when the Phase 2 contracts were written, because H-203 cannot be done without it.

This task runs fourth in Phase 2, after RP-202 and before RP-203, because the authoring guide tells the owner to run both commands.

## 6. Input and output contracts

### 6.1 `blind_case(case)`

Returns a new dictionary with these keys in this order: `schema_version` (the integer 1), `case_id`, then the six `INPUT_FIELDS` taken from `case.model_dump(mode="json")`, then `label`. `label` is a copy of `EMPTY_LABEL` with new, separate empty lists for `invoice_ids` and `credit_ids`. Mutating a returned label must not change `EMPTY_LABEL`.

The result contains no `gold`, no `author_id`, no `seed_id` and no `variant`.

### 6.2 `write_blind(cases, out_dir)`

Creates `out_dir` (`parents=True, exist_ok=True`). For each case with `variant.kind == "original"`, in ascending case ID, writes `out_dir / f"{case.seed_id}.blind.json"` as bytes: `json.dumps(blind_case(case), indent=2, ensure_ascii=False) + "\n"` in UTF-8. Returns the number of files written. Variants are skipped: only originals are labelled twice.

### 6.3 `load_second_labels(directory)`

For every `*.json` under the directory recursively, in sorted path order: parse it; take a copy of `raw["label"]`; remove `labeller_id` from the copy. If the removed value is empty, raise `ValueError(f"{path.name}: labeller_id is empty")`. If `raw["case_id"]` was already loaded, raise `ValueError(f"two labels for {raw['case_id']}")`. Otherwise store `Gold.model_validate(copy)` under `raw["case_id"]`. A form that is not a valid label raises pydantic's `ValidationError`, which is a `ValueError`. Nothing is caught.

### 6.4 `cohen_kappa(pairs)`

`pairs` is a sequence of `(first, second)` category strings.

- Empty input: `None`.
- `observed` = share of pairs with equal members.
- `expected` = sum over every category that appears, in sorted order, of (share of pairs whose first member is that category) times (share whose second member is that category).
- If `expected == 1.0`: `None`. Kappa is undefined when both labellers used one and the same single category.
- Otherwise `(observed - expected) / (1.0 - expected)`.

### 6.5 `agreement(cases, second)`

Considers only original cases, in ascending case ID.

- `missing`: original case IDs with no entry in `second`.
- For each original with a second label, add the pair `(first.decision, other.decision)`.
- If both decisions are `allocate`: count `both_allocate`. If `(customer_id, tuple(sorted(invoice_ids)), tuple(sorted(credit_ids)))` is equal on both sides count `same_allocation`, else the case is a disagreement.
- If both decisions are `review`: count `both_review`. If the families are equal count `same_family`, else add the case ID to `family_differences`. A family difference is not a disagreement.
- If the decisions differ, the case is a disagreement.
- `compared` = number of pairs. `decision_agreements` = pairs with equal members. `kappa = cohen_kappa(pairs)`.

### 6.6 Command

`cases = load_cases(Path(arguments.cases).resolve())` in both subcommands.

`blind`:

| Situation | Printed | Return |
| --- | --- | --- |
| `--out` exists and contains anything | `refusing to write into a non-empty directory: <resolved path>` | 2 |
| Otherwise | `wrote <n> blind files to <resolved path>` | 0 |

`agreement` prints these lines and returns 0:

```
compared: <compared>
missing second label: <len(missing)>
same decision: <decision_agreements> of <compared>
cohen kappa (allocate or review): <kappa with 3 decimals, or the word undefined>
same allocation: <same_allocation> of <both_allocate> both-allocate
same review family: <same_family> of <both_review> both-review
```

followed by one line `missing\t<case_id>` per missing case, then one line `adjudicate\t<case_id>` per disagreement, then one line `family\t<case_id>` per family difference.

The command prints no email text, no rationale and no label content. It does not judge the kappa value. The owner does (H-203: below 0.8, fix the guide and relabel before sealing).
