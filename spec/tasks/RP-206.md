## 1. Objective and rationale

Four commands for the owner, and the functions behind them.

| Command | What it does |
| --- | --- |
| `split` | Divides expanded cases into a development set and a test set, by seed. Refuses to write the test set inside the repository. |
| `commit` | Writes the commitment (counts and one SHA-256 over every test case) and the sentence fingerprints of the test set. Refuses to overwrite either. |
| `verify` | Recomputes the commitment from a test directory and compares. |
| `log` | Appends one row to the access log. |

Why by seed: the variants of one seed share a ledger and a label. If they were on both sides, the test set would have been seen.

Why a commitment: it fixes the test set before any system runs on it. Anyone can later check that the data that was run is the data that was committed, without the data being public.

Why fingerprints: RP-207 uses them to prove that no sentence of the test set is in the repository, without the repository holding any test text.

You implement tooling and test it on the three example seeds. You never receive, open or request real test seeds (R-11).

## 6. Input and output contracts

### 6.1 `split_seeds(cases, owner_author_ids, dev_count, salt)`

1. A seed's author is the `author_id` of its original case. If a seed among the cases has no original, raise `ValueError(f"seed {seed_id} has no original case")` for the first such seed in ascending order.
2. `owned` = seeds whose author is in `owner_author_ids`, ascending.
3. `others` = the remaining seeds, ordered by `hashlib.sha256(f"{salt}:{seed}".encode("utf-8")).hexdigest()` ascending.
4. `extra = max(0, dev_count - len(owned))`.
5. Return `(sorted(owned + others[:extra]), sorted(others[extra:]))`: development seed IDs, then test seed IDs.

The owner's seeds are always development seeds, whatever `dev_count` is. The result does not depend on the order of `cases`.

### 6.2 `commitment(cases)`

For each case in ascending case ID, feed `f"{case.case_id}\t{case_hash}\n"` (UTF-8) into one SHA-256, where `case_hash` is the hex SHA-256 of `dump_case(case)` encoded as UTF-8. Return a dictionary with these keys in this order: `schema_version` (1), `seed_count`, `case_count`, `allocate_cases`, `review_cases`, `commitment_sha256`.

### 6.3 Sentences and fingerprints

`split_sentences(text)`: `re.split(r"(?<=[.!?])\s+|\n+", text)`, dropping pieces that are empty after `strip()`.

`normalize_sentence(sentence)`: case-fold; collapse every run of whitespace to one space and trim; then remove characters from the start while the first character is not alphanumeric (`str.isalnum`), and from the end while the last is not.

`fingerprint(sentence)`: hex SHA-256 of the normalized sentence in UTF-8.

`text_fingerprints(text)`: the fingerprint of each sentence of `split_sentences(text)` whose normalized form has at least `FINGERPRINT_MIN_WORDS` space-separated words. In sentence order, duplicates kept.

`case_fingerprints(cases)`: the sorted set of `text_fingerprints` over, for every case, the payment's `remittance_reference` and each email's `subject` and `body`. Nothing else. The rationale, descriptions, credit reasons and names are not fingerprinted: generated rationales are constants in this repository, and the rest is too short to be a reliable signal.

### 6.4 `append_access_log(path, date, commit, purpose)`

Raises `ValueError` when:

| Condition | Message |
| --- | --- |
| `date` does not fully match `\d{4}-\d{2}-\d{2}` | `date must be YYYY-MM-DD` |
| `commit` does not fully match `[0-9a-f]{7,40}` | `commit must be 7 to 40 lowercase hex characters` |
| `purpose` is blank, or contains `|` or a newline | `purpose must be one non-empty line without a pipe character` |

Otherwise: the existing content, or `ACCESS_LOG_HEADER` when the file does not exist, plus the row ``f"| {date} | `{commit}` | {purpose.strip()} |\n"``, written with `write_bytes`. The date is an argument. This function never reads a clock.

`write_json(path, value)`: `json.dumps(value, indent=2, ensure_ascii=False) + "\n"` as UTF-8 bytes.

### 6.5 Command `split`

In this order:

| Step | Situation | Printed | Return |
| --- | --- | --- | --- |
| 1 | The resolved `--test-out` is `repo_root` or lies under it | `the test split must be stored outside the repository` | 2 |
| 2 | `--dev-out` or `--test-out` exists and contains anything, checked in that order | `refusing to write into a non-empty directory: <path>` | 2 |
| 3 | `validate_cases(load_cases(expanded))` returns issues | `refusing to split: <n> validation issues` | 1 |
| 4 | Otherwise | See below | 0 |

Step 4: call `split_seeds(cases, owner_author list, dev_count, salt)`. Write each development case to `dev_out / seed_id / f"{kind}.{index}.json"` and each test case likewise under `test_out`, with `write_case`. Write the record to `--record` with `write_json`, keys in this order: `schema_version` (1), `salt`, `dev_count_requested`, `owner_author_ids` (sorted), `dev_seed_ids`, `dev_case_count`, `test_seed_count`, `test_case_count`. Print `dev: <seeds> seeds, <cases> cases` and `test: <seeds> seeds, <cases> cases`.

The record names development seeds only. It never lists a test seed ID.

"Lies under" is tested on resolved paths with `path == parent or parent in path.parents`.

### 6.6 Command `commit`

| Step | Situation | Printed | Return |
| --- | --- | --- | --- |
| 1 | `--out` or `--fingerprints` exists, checked in that order | `refusing to overwrite <path>` | 2 |
| 2 | The test cases have validation issues | `refusing to commit: <n> validation issues` | 1 |
| 3 | Otherwise | See below | 0 |

Step 3: `record = commitment(cases)`, then add the key `sealed_on` with the `--sealed-on` value as the last key. Write `record` to `--out`. Write `{"schema_version": 1, "min_words": 5, "sha256": case_fingerprints(cases)}` to `--fingerprints`. Print three lines: `sealed <case_count> cases in <seed_count> seeds`, `commitment_sha256: <hash>`, `sentence fingerprints: <n>`.

A commitment is never overwritten. A changed test set is a new version with new file names, decided by the owner.

### 6.7 Commands `verify` and `log`

`verify`: load the recorded commitment; compute `commitment(load_cases(test))`. If every key of the computed dictionary has the same value in the recorded one, print `commitment matches: <hash>` and return 0. Otherwise print `commitment does NOT match` and return 1. The extra recorded key `sealed_on` is ignored.

`log`: call `append_access_log`, print `logged access on <date>`, return 0. A `ValueError` is not caught.

No command prints a case ID of a test case, a seed ID of a test seed, or any text of a case.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| `dev_count` smaller than the number of owner seeds | All owner seeds are development seeds, and no other seed is |
| `dev_count` larger than the number of seeds | Every seed is a development seed, the test list is empty |
| Two runs with the same cases, owner list, count and salt | Same split |
| A sentence of fewer than five words | No fingerprint |
| The same sentence quoted, bulleted or commented | Same fingerprint, because leading and trailing non-alphanumeric characters are removed |
| `--test-out` given as a relative path that resolves into the repository | Refused |
