## 1. Objective and rationale

A test that fails when any sentence of a sealed test message appears in any text file of the repository.

How it works without the test data: `commit` (RP-206) writes one-way fingerprints of the test sentences to `bench/TEST_FINGERPRINTS.json`. This task hashes every sentence of every text file in the repository the same way and looks for a match. The repository never holds test text, and the guard runs in CI.

Why sentences and not seed IDs, as the first scope note said: a seed ID is a counter. Finding `S014` in a file proves nothing, and not finding it proves nothing either. A copied sentence is what a leak looks like: a fixture, a prompt example, a note in a document.

Until the owner has sealed a test split, the fingerprint file does not exist and the repository test passes trivially. The unit tests prove the guard works on a planted sentence.

## 5. Interfaces

```python
TEXT_SUFFIXES = (
    ".py", ".md", ".json", ".txt", ".ts", ".tsx", ".js", ".mjs", ".yml", ".yaml",
    ".toml", ".ini", ".in", ".lock", ".css", ".html", ".csv",
)
SKIPPED_DIRECTORIES = (
    ".git", "node_modules", ".next", "out", ".venv", "venv", "__pycache__",
    ".pytest_cache", ".hypothesis", ".mypy_cache", ".ruff_cache",
)

def file_fingerprints(path: Path) -> Set[str]
def find_leaks(root: Path, fingerprints: Set[str]) -> List[str]
def load_fingerprints(path: Path) -> Set[str]
```

One private helper, `_strings(value)`, yields every string inside a parsed JSON value: a string itself; for a dictionary each key as `str(key)` and then the strings of each value; for a list the strings of each item. Other types yield nothing.

## 6. Input and output contracts

`file_fingerprints(path)`:

1. Read the file as UTF-8. On `UnicodeDecodeError` or `OSError` return an empty set.
2. Start with `set(text_fingerprints(text))` of the whole file text.
3. If the suffix is `.json`: try `json.loads(text)`. On success add `text_fingerprints(value)` for every string from `_strings`. On `ValueError` add nothing more.
4. Return the set.

Step 3 exists because a sentence inside a JSON string sits between quotes and escapes, and can start or end mid-line in the raw text.

`find_leaks(root, fingerprints)`:

1. If `fingerprints` is empty, return `[]` without reading any file.
2. For every path of `sorted(root.rglob("*"))`: skip it when any part of its path relative to `root` is in `SKIPPED_DIRECTORIES`; skip it when it is not a file or its suffix is not in `TEXT_SUFFIXES`; otherwise, if `file_fingerprints(path)` shares an element with `fingerprints`, record the relative path in POSIX form.
3. Return the recorded paths, which are already in sorted order.

`load_fingerprints(path)`: an empty set when the file does not exist, otherwise `set(json.loads(...)["sha256"])`.

`.gitignore`: append exactly these two lines after the current last line, each ended by a newline:

```
bench/test/
bench/sealed/
```

They are a second line of defence for an owner who keeps a local copy next to the code. The first line of defence is `split`, which refuses to write the test set into the repository.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| The sentence appears with other case, extra spaces, or behind `#`, `>`, `-` or quotes | Found. Normalization removes these. |
| The sentence appears with one word changed | Not found. The guard catches copies, not paraphrases. This is a stated limit. |
| A sentence of fewer than five words | Never fingerprinted, so never found |
| A file in `node_modules` or `.git` | Not read |
| A file that is not valid UTF-8 | Skipped |
| A `.json` file that does not parse | Treated as plain text only |
