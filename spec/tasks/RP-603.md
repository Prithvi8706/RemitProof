## 1. Objective and rationale

Add a mutation runner that uses the standard library only, run it on the five files that decide what the search returns and what may be authorized, and commit its report together with a triage record.

A mutant is one small change to one file, for example `<` turned into `<=`. If the tests still pass with the change in place, either the change does not matter (an equivalent mutant) or no test notices a real difference (a test gap). Telling these apart needs a person. So the tool finds the survivors, and the triage record says for each one which of the two it is.

### Why no new dependency

Two tools were looked up on PyPI on 2026-11-16. `mutmut` 3.8.1 is the newest release, and the newest that installs under Python 3.9 is 3.3.1. `cosmic-ray` 8.9.0 installs under both. Either one means another regeneration of the development lock (DD-12), which already carries the numpy problem of OD-6. The runner written here is about 250 lines, has no dependency, runs unchanged on Python 3.9 and 3.13, and gives the same report on both.

Trade-off: six operators, where the tools above have several dozen. Section 9 lists what is not mutated. A surviving mutant is a real finding. A killed mutant says only that some test notices that one change.

### Why no mutant count is pinned

The mutants of a file depend on its exact text. The five target files are written by implementers from contracts, and two implementers write different text for the same contract. So this contract pins the behaviour of the tool on small fixed examples, and the agreement between the committed report and the committed triage record. It does not pin how many mutants your files have, how many are killed, or which survive.

## 6. Input and output contracts

### 6.1 A mutant

A dict with: `id`, `file`, `line` (1-based), `column` (0-based), `operator`, `original`, `replacement`, and the two character offsets `begin` and `end` into the source. `id` is `f"{file}:{line}:{column}:{operator}"`. `line` and `column` are those of `begin`.

`apply_mutant(source, mutant)` is `source[:begin] + replacement + source[end:]`.

### 6.2 `mutants_of`

Raises `ValueError(f"{relative_path} is not ASCII")` when the source has a character outside ASCII. With ASCII text the column offsets of `ast` are character offsets.

Parse the source with `ast.parse` and visit every node with `ast.walk`. The six operators:

| Operator | Node | What is replaced |
| --- | --- | --- |
| `CMP` | Each operator of an `ast.Compare` that is one of `<`, `<=`, `>`, `>=`, `==`, `!=` | `<` by `<=`, `<=` by `<`, `>` by `>=`, `>=` by `>`, `==` by `!=`, `!=` by `==` |
| `BOOL` | Each pair of neighbouring operands of an `ast.BoolOp` | `and` by `or`, `or` by `and` |
| `ARITH` | An `ast.BinOp` with `+` or `-` | `+` by `-`, `-` by `+` |
| `AUG` | An `ast.AugAssign` with `+=` or `-=` | `+=` by `-=`, `-=` by `+=` |
| `NOT` | An `ast.UnaryOp` with `not` | The text from the start of the node to the start of its operand is removed |
| `NUM` | An `ast.Constant` whose value has exactly the type `int` (so not `bool`) | The text of the node by `str(value + 1)` |

For `CMP`, `BOOL`, `ARITH` and `AUG` the operator token is located in the source text between the end of the operand on its left and the start of the operand on its right. The first occurrence of the token in that gap is the one replaced. This is what makes `(a) < (b)` work, where the gap is `) < (`.

A chained comparison `a < b <= c` gives one mutant per operator. `a or b or c` gives two.

Before recording a mutant, check that `source[begin:end]` equals `original`. If not, raise `ValueError(f"{relative_path}: expected {original!r} at offset {begin}")`.

Return the mutants sorted by `begin`, and for equal `begin` by the position of the operator in `OPERATORS`.

`generate(root, targets)` concatenates `mutants_of(path, text of root / path)` over the targets in their order.

### 6.3 Running tests against one mutant

One helper runs `[sys.executable, "-m", "pytest", "-q", "-x", "-p", "no:cacheprovider", *tests]` with the working directory at the root of a copy of the repository, the environment variable `PYTHONDONTWRITEBYTECODE=1` added, output discarded, and a timeout. Its result:

| pytest | Result |
| --- | --- |
| Exit code 0 | `passed` |
| Exit code 1 or 2 | `failed`. Code 2 is what pytest returns when a mutant breaks an import. |
| Timeout | `timeout` |
| Any other exit code | `RuntimeError(f"pytest exited with {code} for {' '.join(tests)}")` |

`PYTHONDONTWRITEBYTECODE` matters. Two mutants of the same file can have the same size and the same modification second, and a cached bytecode file would then make the second mutant run the first one's code.

A worker copies the repository once into a temporary directory with `shutil.copytree`, ignoring `.git`, `frontend`, `node_modules`, `__pycache__`, `.hypothesis`, `.pytest_cache`, `.next` and `.venv`. For each of its mutants it writes the changed text into the copy, runs the tests, and writes the original text back in a `finally` block. The repository itself is never changed.

With `workers` greater than 1 the jobs are dealt out as `jobs[i::workers]`, one copy and one thread per worker.

### 6.4 `run`

1. `check_baseline(root, targets)`: for each target, its own tests must give `passed` on the unchanged root. Otherwise `RuntimeError(f"the tests for {relative_path} do not pass before any mutation")`.
2. Generate the mutants. Stage one: run each against its file's own tests with `quick_timeout`.
3. The survivors of stage one are those with `passed`. If there are any and `quick` is false: first run `full_suite` on the unchanged root with `full_timeout`. If that is not `passed`, raise `RuntimeError("the full suite does not pass before any mutation")`. Then run each survivor against `full_suite`.
4. Status of a mutant: `killed` if stage one failed. Else `timeout` if either stage timed out. Else `killed_by_full_suite` if stage two failed. Else `survived`.

The check in step 3 is not optional. In the dry run the first version lacked it, an unrelated test was failing, and every survivor was reported as killed by the full suite.

`FULL_SUITE` leaves out `test_mutation_run.py` for the same reason: that file reads the two committed documents, which do not exist during the first run.

The report:

| Key | Value |
| --- | --- |
| `format_version` | `1` |
| `full_suite_stage` | `not quick` |
| `operators` | `list(OPERATORS)` |
| `files` | One dict per target in order: `file`, `sha256` (of the file's bytes with CRLF replaced by LF), `tests` (list), `mutants` (count), then one count per status in `STATUSES` |
| `mutants` | One dict per mutant in generation order: `id`, `file`, `line`, `column`, `operator`, `original`, `replacement`, `status`. Not `begin` and `end`. |

No time, date, host name or Python version. `report_bytes(report)` is `json.dumps(report, indent=2, sort_keys=True)` plus one newline, as UTF-8.

### 6.5 The triage record

A JSON object with `format_version` 1 and `entries`, a dict from mutant ID to `{"class": ..., "note": ...}`.

| Class | Meaning |
| --- | --- |
| `equivalent` | The change cannot alter any result. The note says why. |
| `test_gap` | The change alters behaviour and no test notices. The note names the task that adds the test. |
| `accepted` | The change alters behaviour in a way the owner accepts as untested. The note says why. |
| `open` | Not yet triaged |

`open_triage(report)` returns a record with one entry per mutant whose status is `survived` or `timeout`, each `{"class": "open", "note": "not yet triaged"}`.

`triage_problems(report, triage)` returns messages, in this order:

1. `"triage record has an unknown format version"` if `format_version` is not 1.
2. For each ID with status `survived` or `timeout`, sorted, that has no entry: `f"no triage entry for {id}"`.
3. For each entry, sorted by ID, up to three messages in this order: `f"triage entry for a mutant that did not survive: {id}"` if the ID is not a survivor; `f"unknown triage class for {id}: {class}"` if the class is not in `TRIAGE_CLASSES`; `f"empty triage note for {id}"` if the note is empty or only spaces.

### 6.6 `stale_files`

For each row of `report["files"]`: hash the file under `root` as in 6.4. If the file is missing or the hash differs from the row's `sha256`, the file name is in the result.

### 6.7 `main`

| Mode | Behaviour | Exit |
| --- | --- | --- |
| `--list` | For each target `f"{count:4d}  {path}"`, then `f"{total:4d}  total"`. Writes nothing. | 0 |
| `--run`, `--workers` below 1 | `parser.error("--workers must be at least 1")` | 2 |
| `--run`, the report exists, no `--force` | Prints `refusing to overwrite <report path>; pass --force after review`. Runs nothing. | 2 |
| `--run` otherwise | Runs, writes the report, prints `wrote <report path>`. If no triage file exists, writes `report_bytes(open_triage(report))` there and prints `wrote <triage path>`. An existing triage file is never overwritten. Then one line per target: `f"{mutants:4d} mutants, {killed} killed, {killed_by_full_suite} by the full suite, {survived} survived, {timeout} timed out  {file}"`. | 0 |
| `--check`, a file is missing | Prints `file is missing: <path>` for the first missing one, the report before the triage record | 2 |

Paths are printed as resolved absolute paths.

## 8. Algorithm

Section 6.2 is the algorithm. One worked example, which is also a test parameter. Source `x = (a) < (b) <= c`, one line:

1. The `Compare` node has operands `a`, `b`, `c` and operators `<`, `<=`.
2. First operator: the gap between the end of `a` (offset 6) and the start of `b` (offset 11) is `) < (`. The token `<` is at position 2 of the gap, so `begin` is 8. The mutant replaces offsets 8 to 9 by `<=` and gives `x = (a) <= (b) <= c`.
3. Second operator: the gap between the end of `b` (offset 12) and the start of `c` (offset 17) is `) <= `. The token `<=` is at position 2, so `begin` is 14. The mutant gives `x = (a) < (b) < c`.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| A string that contains `<` or a number | Not mutated. Only `ast` nodes are visited, and a string is a constant of type `str`. |
| `True`, `False` | Not mutated. Their type is `bool`. |
| `is`, `is not`, `in`, `not in`, `*`, `//`, `%`, `**`, unary minus, a float | Not mutated. Stated limits of the six operators. |
| Statement deletion, changed return values, changed default arguments | Not done. Stated limits. |
| A mutant that makes the code loop without end | `timeout` after `quick_timeout` or `full_timeout`. It needs a triage entry like a survivor. |
| A target file changed after the report was made | `--check` prints `report is stale for <file>` and exits 1. No test in the suite fails because of it: a later task that edits a target is not blocked. The owner reruns the tool before the sealed run (H-601). |
| A CRLF checkout | The hash normalizes CRLF to LF |
| The run is interrupted | Nothing is written. The temporary copies are removed by `tempfile`. The repository is never changed. |
