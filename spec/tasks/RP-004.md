## 1. Objective and rationale

Add a script that runs the rules-only baseline and the verifier-only baseline over the legacy corpus, scores both against ground truth, and writes a deterministic JSON report. Commit that report. Add tests that compare the committed report with a fresh run byte for byte and cross-check the scoring against numbers the existing evaluator already published.

Why: this makes finding F1 a permanent, reproducible artifact without touching the evaluator or the published snapshot (DD-02). From now on, any change in what the deterministic checks authorize on the legacy corpus changes the report and fails a test, which forces a reviewed generation bump (DD-14).

## 6. Input and output contracts

**`default_report_path(repo_root)`**: `repo_root / "audit" / CURRENT_AUDIT_GENERATION / REPORT_FILENAME`.

**`_sha256_json(value)`**: SHA-256 hex of `json.dumps(value, sort_keys=True, separators=(",", ":")).encode("utf-8")`.

**`dataset_sha256(dataset, ground_truth)`**: `_sha256_json` of this structure, where each list is `[item.model_dump(mode="json") for item in ...]` in dataset order:

```
{"dataset": {"payments": [...], "invoices": [...], "customers": [...], "credits": [...], "emails": [...]},
 "ground_truth": ground_truth}
```

**`matches_truth(customer_id, invoice_ids, credit_ids, truth)`**: true only when `truth["should_resolve"]` is truthy, `customer_id == truth["correct_customer"]`, `set(invoice_ids) == set(truth["correct_invoices"])` and `set(credit_ids) == set(truth["correct_credits"])`. Returns a `bool`.

**`run_cases(dataset, ground_truth)`**: one row per payment, in dataset order. Uses one `VerifierOnlyInvestigator` for the whole run and calls `process_payment(payment.payment_id, dataset, investigator)` once per payment. Let `result` be the return value, `truth` the ground-truth row for that payment, `outcome = investigator.outcomes.get(payment.payment_id)` (may be `None`), `baseline_resolved = result.baseline.status == "matched"`, and `final_auto = result.decision.decision in {"matched_normally", "resolved"}`. Row keys, exact:

| Key | Value |
| --- | --- |
| `payment_id` | `payment.payment_id` |
| `split` | `truth["split"]` |
| `is_exception` | `bool(truth["is_exception"])` |
| `exception_class` | `truth["exception_class"]` |
| `expected_should_resolve` | `bool(truth["should_resolve"])` |
| `rules_only_baseline_decision` | `"resolve"` if `baseline_resolved` else `"abstain"` |
| `rules_only_baseline_correct_resolution` | `baseline_resolved and matches_truth(result.baseline.customer_id, result.baseline.matched_invoices, result.baseline.matched_credits, truth)` |
| `verifier_only_decision` | `"resolve"` if `final_auto` else `"abstain"` |
| `verifier_only_correct_resolution` | `final_auto and matches_truth(result.decision.customer_id, result.decision.invoice_ids, result.decision.credit_ids, truth)` |
| `verifier_only_reason` | `outcome.reason` if `outcome` is not `None`, else `"not_consulted"` |
| `alternatives_considered` | `outcome.alternatives_considered` if `outcome` is not `None`, else `None` |
| `authorizable_allocations` | `len(outcome.authorizable_allocation_ids)` if `outcome` is not `None`, else `None` |
| `selected_customer` | `result.decision.customer_id` if `final_auto`, else `None` |
| `selected_invoices` | `sorted(result.decision.invoice_ids)` if `final_auto`, else `[]` |
| `selected_credits` | `sorted(result.decision.credit_ids)` if `final_auto`, else `[]` |

The two `..._correct_resolution` values must be real booleans.

**`comparison_rows(rows)`**: the rows where `is_exception` is true and `rules_only_baseline_decision == "abstain"`, in the same order.

**`summarize(rows, system)`**: raises `ValueError(f"unknown system: {system}")` when `system` is not in `SYSTEMS`. Otherwise, with `resolved` = rows whose `<system>_decision == "resolve"` and `abstained` = rows whose `<system>_decision == "abstain"`, returns exactly:

| Key | Value |
| --- | --- |
| `resolved` | `len(resolved)` |
| `correct_resolutions` | Number of `resolved` rows whose `<system>_correct_resolution` is true |
| `wrong_auto_resolutions` | `resolved - correct_resolutions` |
| `correct_abstentions` | Number of `abstained` rows with `expected_should_resolve` false |
| `false_escalations` | Number of `abstained` rows with `expected_should_resolve` true |

**`_section(rows)`**: with `scoped = comparison_rows(rows)`, returns `{"total_receipts": len(rows), "comparison_record_count": len(scoped), "systems": {system: summarize(scoped, system) for system in SYSTEMS}}`.

**`build_report(dataset, ground_truth)`**: with `rows = run_cases(...)`, returns exactly these keys:

| Key | Value |
| --- | --- |
| `report_format_version` | `REPORT_FORMAT_VERSION` |
| `audit_generation` | `CURRENT_AUDIT_GENERATION` |
| `dataset_sha256` | `dataset_sha256(dataset, ground_truth)` |
| `scope` | `SCOPE` |
| `systems` | `{"rules_only_baseline": "baseline_match on the retrieved candidate bundle; no model", "verifier_only": "resolve only when exactly one financially valid allocation passes the existing proof and sufficiency checks; no model"}` |
| `overall` | `_section(rows)` |
| `by_split` | For each distinct `split` value in ascending order: `_section` of the rows with that split |
| `cases` | `comparison_rows(rows)` sorted by `payment_id` |

No timestamp, duration, latency, hostname, path or version string appears anywhere in the report.

**`report_bytes(report)`**: `(json.dumps(report, indent=2, sort_keys=True) + "\n").encode("utf-8")`.

**`main(argv)`** command line:

| Argument | Meaning |
| --- | --- |
| `--write` or `--check` | Exactly one is required |
| `--data PATH` | Default `str(REPO_ROOT / "data")` |
| `--output PATH` | Default `str(default_report_path(REPO_ROOT))` |
| `--force` | Allows `--write` to replace an existing report |

In both modes, first compute `content = report_bytes(build_report(load_dataset(data_dir), load_ground_truth(data_dir)))` from the resolved `--data` path.

| Mode | Situation | Printed line | Return |
| --- | --- | --- | --- |
| `--write` | Output exists, no `--force` | `refusing to overwrite <path>; pass --force after review` | `EXIT_USAGE` |
| `--write` | Otherwise | `wrote <path>` | `EXIT_OK` |
| `--check` | Output file missing | `report is missing: <path>` | `EXIT_USAGE` |
| `--check` | File bytes, after replacing `b"\r\n"` with `b"\n"`, differ from `content` | `report differs from a fresh run: <path>` | `EXIT_DRIFT` |
| `--check` | Equal | `report matches a fresh run: <path>` | `EXIT_OK` |

`--write` uses `atomic_write_bytes`. `--check` never writes.

## 8. Algorithm

The only logic is the scoring in section 6. Pseudocode for the counts:

```
summarize(rows, system):
    resolved  = [r for r in rows if r[system + "_decision"] == "resolve"]
    abstained = [r for r in rows if r[system + "_decision"] == "abstain"]
    correct   = count(r in resolved where r[system + "_correct_resolution"])
    return resolved, correct, len(resolved) - correct,
           count(r in abstained where not r["expected_should_resolve"]),
           count(r in abstained where r["expected_should_resolve"])
```

Every row is counted once: `resolved + correct_abstentions + false_escalations == len(rows)`.

A resolution of a case that should not be resolved counts as a wrong automatic resolution, because `matches_truth` returns false when `should_resolve` is false.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| A payment with no ground-truth row | `KeyError` propagates. Do not catch it. |
| A payment the investigator was never asked about (replay gate, rules-only match, status gate) | `verifier_only_reason` is `"not_consulted"`; the two count fields are `None` |
| A rules-only match | `verifier_only_decision` is `"resolve"` because the pipeline decision is `matched_normally`. Such rows are outside the comparison scope. |
| Running the script twice | Byte-identical output |
| Windows checkout with CRLF in the committed report | `--check` still passes, because it normalizes before comparing |
