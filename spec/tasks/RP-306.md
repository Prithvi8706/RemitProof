## 1. Objective and rationale

One command turns a directory of cases and one decisions file per system into a results table, as JSON and as Markdown. Every system is scored on the same cases, with the same denominators.

This task runs third in Phase 3, before the baselines, so that each baseline can be read in a table as soon as it exists.

What the table contains:

| Part | Content |
| --- | --- |
| Scopes | `exceptions`, `easy`, `all`. Headline figures are on exceptions. |
| Strata | Exceptions by variant kind, and exceptions by label |
| Paired comparisons | For each requested pair: discordant counts and exact McNemar p-value, for "correct decision" and for "wrong allocation", each Holm-adjusted across the requested pairs |

The `rules_only` decisions are required, because they define which cases are easy.

## 6. Input and output contracts

### 6.1 `build_report(cases, decisions_by_system, comparisons)`

Checks, in this order:

| Condition | Raises `ValueError` with |
| --- | --- |
| `REFERENCE_SYSTEM` is not a key of `decisions_by_system` | `decisions for rules_only are required: they define the easy cases` |
| `check_complete` fails for a system, systems in ascending name | `f"{name}: {message of the error}"` |
| A comparison names a system without decisions | `comparison names unknown system <name>` |

Then, with the cases in ascending case ID and the system names sorted:

- `easy = easy_case_ids(cases, decisions_by_system["rules_only"])`.
- Scope `exceptions` is every case not in `easy`; `easy` is every case in it; `all` is every case.
- For a subset of cases, "per system" means `{name: metrics(subset, decisions_by_system[name])}` over the sorted names.

Return a dictionary with these keys in this order:

| Key | Value |
| --- | --- |
| `report_version` | 1 |
| `case_count`, `seed_count` | Counts over all cases |
| `easy_count`, `exception_count` | Sizes of the two scopes |
| `systems` | The sorted names |
| `scopes` | For each scope in `SCOPES` order: per system |
| `exceptions_by_variant_kind` | For each kind in `VARIANT_KINDS` order that occurs among the exceptions: per system on the exceptions of that kind |
| `exceptions_by_gold_decision` | For `allocate` then `review`, when it occurs among the exceptions: per system on those exceptions |
| `comparisons` | One row per requested pair, in the order given |

A comparison row for `(first, second)`, computed on the exceptions:

```
{"first": first, "second": second, "scope": "exceptions",
 "correct":          {"first_only": b, "second_only": c, "p": mcnemar_exact(b, c), "p_holm": ...},
 "wrong_allocation": {"first_only": b, "second_only": c, "p": mcnemar_exact(b, c), "p_holm": ...}}
```

For `correct`, a case is a hit for a system when its outcome is `correct_allocation` or `correct_review`. For `wrong_allocation`, when its outcome is `wrong_allocation`. `first_only` counts cases that are a hit for the first system and not for the second. `second_only` is the reverse.

`p_holm`: `holm` applied to the `p` values of all rows, separately for `correct` and for `wrong_allocation`.

### 6.2 `render_markdown(report)`

Lines joined with `\n`. The text ends with one newline. Structure:

1. `# RemitBench results table`, blank line.
2. `<case_count> cases from <seed_count> seeds. <easy_count> easy cases, <exception_count> exceptions.`
3. `An easy case is one the rules-only system allocates correctly. Headline figures are on exceptions.`, blank line.
4. `## By scope`, blank line, then one table per scope with the heading `### <scope>`.
5. `## Exceptions by variant kind`, blank line, one table per kind.
6. `## Exceptions by label`, blank line, one table per label.
7. `## Paired comparisons on exceptions`, blank line, then either `None requested.` and a blank line, or the comparison table and a blank line.

A table is: the heading, a blank line, the header row, the separator row, one row per system in ascending name, a blank line. Header row, exactly:

```
| System | Cases | Correct allocation | Wrong allocation | Correct review | False escalation | False authorization rate (one-sided 95% bound) | By seed | Coverage (95% interval) | By seed |
```

The separator has ten `---` cells. Cell formats, with `pct(x) = f"{100.0 * x:.1f}%"`:

| Cell | Format | When the proportion is `None` |
| --- | --- | --- |
| False authorization rate | `f"{k}/{n} = {pct(rate)} (at most {pct(upper_95_one_sided)})"` | `n/a` |
| Its "By seed" | `f"{pct(low)} to {pct(high)}"` from `seed_interval_95` | `n/a`, also when `seed_interval_95` is `None` |
| Coverage | `f"{k}/{n} = {pct(rate)} ({pct(low)} to {pct(high)})"` from `interval_95` | `n/a` |
| Its "By seed" | As above | `n/a` |

Comparison table header: `| First | Second | Measure | First only | Second only | Exact McNemar p | Holm-adjusted p |`, a separator of seven cells, and two rows per comparison: measure `Correct decision`, then `Wrong allocation`. Both p-values are printed with `:.4f`.

### 6.3 Command `table`

In this order:

| Step | Situation | Printed | Return |
| --- | --- | --- | --- |
| 1 | `--out-json` or `--out-md` exists, checked in that order | `refusing to overwrite <path>` | 2 |
| 2 | A `--decisions` value is not `NAME=FILE` with non-empty parts, or repeats a name | `--decisions must be NAME=FILE with distinct names: <value>` | 2 |
| 3 | A `--compare` value is not `FIRST:SECOND` with non-empty parts | `--compare must be FIRST:SECOND: <value>` | 2 |
| 4 | Otherwise | `<systems> systems, <case_count> cases, <exception_count> exceptions` | 0 |

Split `NAME=FILE` at the first `=` and `FIRST:SECOND` at the first `:` (`str.partition`). Read each file with `read_decisions`. Step 4 writes `json.dumps(report, indent=2) + "\n"` to `--out-json` and `render_markdown(report)` to `--out-md`, both as UTF-8 bytes, creating parent directories. A `ValueError` from `build_report` is not caught. Nothing is written before every check has passed.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| No easy case | The `easy` scope has 0 cases per system and every proportion cell is `n/a` |
| A stratum with no `allocate` label, for example twins | Coverage is `None`, shown as `n/a` |
| No comparison requested | `comparisons` is an empty list; the Markdown says `None requested.` |
| A system compared with itself | Allowed. Both discordant counts are 0 and `p` is 1.0. |
