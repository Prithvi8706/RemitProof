## 1. Objective and rationale

One command runs one system at least twice over the same cases and writes, into a new directory: one decisions file per run, and a manifest.

The manifest records what a reader needs to trust a number: which system, which code commit, which cases (by hash), which model and prompt (by digest and hash), and whether the runs agreed with each other.

Why at least two runs: a model at temperature 0 is usually deterministic and sometimes is not. One run cannot tell. If the runs differ, the owner reruns with `--repeats 5` and reports the spread.

Why the date and the commit are arguments: the tool never reads a clock or a repository state. The same inputs give the same manifest bytes.

## 6. Input and output contracts

### 6.1 `record_run`

1. If `repeats < 2`: raise `ValueError("repeats must be at least 2: one run cannot show determinism")`.
2. If `out_dir` exists and contains anything: raise `ValueError(f"refusing to write into a non-empty directory: {out_dir}")`.
3. Create `out_dir` (`parents=True, exist_ok=True`).
4. For `number` from 1 to `repeats`: `decisions = run_system(system, cases)`; `text = dump_decisions(decisions)`; write it as UTF-8 bytes to `out_dir / f"{name}.run{number}.jsonl"`; remember the file name and the hex SHA-256 of the text.
5. `differing` = the sorted case IDs whose decision in any later run is not equal to its decision in run 1.
6. `sealed = commitment(cases)`.
7. Build the manifest with these keys in this order: `manifest_version` (1), `system`, `code_commit`, `recorded_on`, `case_count`, `seed_count` (both from `sealed`), `cases_sha256` (`sealed["commitment_sha256"]`), `repeats`, `decision_files` (a list of `{"file": ..., "sha256": ...}` in run order), `deterministic` (`True` when `differing` is empty), `differing_case_count`, `provenance`.
8. Write `json.dumps(manifest, indent=2) + "\n"` as UTF-8 bytes to `out_dir / f"{name}.manifest.json"`. Return the manifest.

The manifest gives the number of differing cases, never their IDs. On the sealed test split a case ID is test information.

Step 1 runs before anything is created.

### 6.2 `build_system(name, model, model_digest, host)`

| Name | Returns |
| --- | --- |
| A key of `MODEL_FREE_SYSTEMS` | `(MODEL_FREE_SYSTEMS[name], {"model": None})` |
| A model system with `model` or `model_digest` missing or empty | Raises `ValueError(f"--model and --model-digest are required for {name}")` |
| `llm_abstain` | `baseline = AbstainingModel(host, model, model_digest)`; `(llm_abstain(baseline), baseline.provenance())` |
| `proposal_pipeline` | `investigator = OllamaInvestigator(host=host, model=model, model_digest=model_digest)`; `(proposal_pipeline(investigator), investigator.public_provenance())` |
| `basic_validation` | The same investigator; `(basic_validation(investigator), investigator.public_provenance())` |

A model system without a digest is refused, because a run whose model cannot be identified is not evidence.

### 6.3 Command

In this order:

| Step | Situation | Printed | Return |
| --- | --- | --- | --- |
| 1 | `--code-commit` does not fully match `[0-9a-f]{7,40}` | `--code-commit must be 7 to 40 lowercase hex characters` | 2 |
| 2 | `--recorded-on` does not fully match `\d{4}-\d{2}-\d{2}` | `--recorded-on must be YYYY-MM-DD` | 2 |
| 3 | `build_system` or `record_run` raises `ValueError` | `str(error)` | 2 |
| 4 | Otherwise | `<system>: <repeats> runs of <case_count> cases, deterministic: yes (0 differing)` or `deterministic: no (<n> differing)` | 0 |

`build_system`, `load_cases` and `record_run` are called inside one `try` that catches `ValueError` only. Non-determinism is reported, not treated as a failure: the return value is 0.

This command does not know which split it is given. The sealed test split is run only through RP-801, which wraps this function and writes the access log.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| A system that answers differently on a later run | `deterministic` is `False`, the count is given, all runs are kept |
| A model that is down for the whole run | Every decision is a review with a reason such as `model_unavailable`. The runs are identical, so `deterministic` is `True`. The owner must look at the decisions before using a run. The manifest cannot know a model was down. |
| An exception other than `ValueError` during a run | Propagates. Files of completed runs stay in the directory, without a manifest. A directory without a manifest is not a recorded run. |
| `--repeats 1` | Refused before anything is written |
