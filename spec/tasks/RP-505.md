## 1. Objective and rationale

Add OR-Tools to the development dependencies so that RP-506 can use its CP-SAT solver as an independent oracle for the hand-written solver (DD-16).

The version is pinned to `9.15.6755`. Looked up during the dry run with `pip index versions ortools`: it is the newest release, and it supports Python 3.9 (`Requires-Python: >= 3.9`, wheels for CPython 3.9 and 3.13 on Linux x86-64, macOS arm64 and Windows x86-64). Unlike Hypothesis in RP-105, keeping Python 3.9 costs no OR-Tools version.

It costs something else. OR-Tools needs `numpy >= 2.0.2`. The newest numpy that supports Python 3.9 is exactly 2.0.2, and numpy 2.0.2 has no wheel for Python 3.13. A lock compiled under Python 3.9 therefore pins numpy 2.0.2, and an install under Python 3.13 builds numpy from source. In the dry run that install succeeded and took 365 seconds without a cache (9 seconds under Python 3.9). It needs a C compiler. See section 9 and owner decision OD-6.

This task adds no test and no code. Runtime dependencies (`backend/requirements.in`, `backend/requirements.lock`) do not change, and nothing under `backend/app/` may import OR-Tools, now or later (DD-12).

## 7. Implementation steps

Run every command from the repository root.

1. Append the line to `backend/requirements-dev.in`.
2. Compile under Python 3.9 with the header command pinned. On Linux or macOS:

```
CUSTOM_COMPILE_COMMAND="python -m piptools compile --generate-hashes --strip-extras --output-file=backend/requirements-dev.lock backend/requirements-dev.in" python3.9 -m piptools compile --generate-hashes --strip-extras --output-file=backend/requirements-dev.lock backend/requirements-dev.in
```

On Windows PowerShell:

```
$env:CUSTOM_COMPILE_COMMAND = "python -m piptools compile --generate-hashes --strip-extras --output-file=backend/requirements-dev.lock backend/requirements-dev.in"
py -3.9 -m piptools compile --generate-hashes --strip-extras --output-file=backend/requirements-dev.lock backend/requirements-dev.in
```

Do not pass `--upgrade`. Without it, pip-tools keeps every existing pin.

3. Inspect `git diff backend/requirements-dev.lock` against section 6. Apply section 9 if needed.
4. Run the commands in section 13.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| The diff removes the `colorama==0.4.6` block (you compiled on Linux or macOS) | Restore that block exactly as it is in `git show HEAD:backend/requirements-dev.lock`: the name line, its two hash lines and its three comment lines, directly before the `exceptiongroup` block. After restoring, the diff must have no deleted line. This happened in the dry run: six deleted lines before the restore, none after. |
| The diff changes the version or a hash of any existing package | Stop. Do not commit the lock. Report the package names. |
| The diff removes any block other than `colorama` | Stop. Report. |
| The resolved numpy is not `2.0.2` | Stop. Either the lock was compiled under another Python version, or numpy published a new release line for Python 3.9. Report the version. |
| The header lines differ from the committed header | `CUSTOM_COMPILE_COMMAND` was not set. Restore the file with `git checkout backend/requirements-dev.lock` and repeat step 2. |
| `pip check` reports a conflict | Stop. Report the full output. |
| Installing under Python 3.13 fails while building numpy | The machine has no C compiler, or no build tools for numpy. Expected on Windows without the Microsoft build tools. This is not a fault of the lock. Report it, skip command 8 of section 13, and leave Python 3.13 to CI. |
| Installing under Python 3.13 takes several minutes | Expected. pip prints "Building wheel for numpy". 365 seconds in the dry run, without a cache. |

What this task knowingly leaves as it is, for the owner (OD-6):

- CI under Python 3.13 builds numpy from source the first time after this lock lands, and again whenever the pip cache for the lock is dropped. Later runs reuse the cached wheel.
- A developer on Windows with Python 3.13 and no compiler cannot install the development lock. Python 3.9 on the same machine can.
