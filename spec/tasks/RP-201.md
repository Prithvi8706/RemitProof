## 1. Objective and rationale

Define the file format of one RemitBench case, and the functions that read and write it byte-identically.

A case is one payment, the ledger around it, the messages around it, and a gold label: what a competent receivables analyst would do with exactly these records. The format reuses the five record models the pipeline already has, so a case can be run without conversion.

Why a new package and not `backend/app/`: a case carries its gold label. Runtime code must never be able to read one (R-11, INV-P5). The package is `backend/remitbench/`. It may import from `app`. Nothing under `backend/app/` may import it, and a test enforces that.

Why `backend/remitbench/` and not `bench/` at the repository root: the suite runs with `backend` on the import path (`backend/pytest.ini`). A package at the root would need a change to how every test is collected. Data and documents live in `bench/` at the root. Code lives in `backend/remitbench/`.

## 3. Current behaviour and references

There is no benchmark tooling. The record models are `Payment`, `Customer`, `Invoice`, `Credit` and `RemittanceEmail`, exported from `backend/app/models/__init__.py`. All five forbid unknown fields. Amounts are `Decimal` with two decimals and serialize as strings in JSON mode (`backend/app/models/payment.py:45`).

The sandbox defines a similar container, `SandboxInput` (`backend/app/api/sandbox.py:33-50`). It caps list lengths at 3 customers, 8 invoices, 3 credits and 4 emails. A benchmark case has no caps. Do not import or reuse `SandboxInput`.

```python

VARIANT_KINDS = ("original", "resample", "human_paraphrase", "llm_paraphrase", "twin", "noise")
GOLD_DECISIONS = ("allocate", "review")
REVIEW_FAMILIES = (
    "ambiguous_allocation", "conflicting_evidence", "missing_document", "unsupported_payer",
    "amount_mismatch", "ineligible_record", "currency_mismatch", "other",
)
SEED_ID_PATTERN = re.compile(r"[A-Z]{1,4}[0-9]{2,4}")
AUTHOR_ID_PATTERN = re.compile(r"[A-Za-z0-9_-]{1,16}")

class Variant(BaseModel)      # extra="forbid"
class Gold(BaseModel)         # extra="forbid"
class BenchCase(BaseModel)    # extra="forbid"

def dump_case(case: BenchCase) -> str
def write_case(case: BenchCase, path: Path) -> None
def load_case(path: Path) -> BenchCase
```

## 6. Input and output contracts

### 6.1 Validation rules

Each model has one `@model_validator(mode="after")` that raises `ValueError` with the message shown.

`Variant`:

| Condition | Message |
| --- | --- |
| `kind == "original"` and `parent_case_id is not None` | `an original case has no parent_case_id` |
| `kind != "original"` and `parent_case_id is None` | `a variant case needs parent_case_id` |
| `(operator is None) != (generator_seed is None)` | `operator and generator_seed are set together or not at all` |

`Gold`:

| Condition | Message |
| --- | --- |
| `decision == "allocate"` and (`customer_id is None` or `invoice_ids` empty) | `an allocate label needs customer_id and at least one invoice` |
| `decision == "allocate"` and `review_family is not None` | `an allocate label has no review_family` |
| `decision == "review"` and (`customer_id is not None` or `invoice_ids` or `credit_ids` non-empty) | `a review label carries no allocation` |
| `decision == "review"` and `review_family is None` | `a review label needs review_family` |
| `invoice_ids` has a repeated value | `duplicate invoice in the label` |
| `credit_ids` has a repeated value | `duplicate credit in the label` |

`BenchCase`:

| Condition | Message |
| --- | --- |
| `SEED_ID_PATTERN.fullmatch(seed_id) is None` | `seed_id must be 1 to 4 capital letters followed by 2 to 4 digits` |
| `AUTHOR_ID_PATTERN.fullmatch(author_id) is None` | `author_id must be 1 to 16 letters, digits, hyphens or underscores` |
| `case_id != f"{seed_id}.{variant.kind}.{variant.index}"` | `case_id must be <expected>` with the expected value filled in |
| `variant.parent_case_id` is set and does not start with `f"{seed_id}."` | `parent_case_id must belong to the same seed` |

These models check shape only. Whether the label is consistent with the ledger is RP-202.

### 6.2 Serialization

`dump_case(case)` returns exactly `json.dumps(case.model_dump(mode="json"), indent=2, ensure_ascii=False) + "\n"`. No `sort_keys`. Key order is field order.

`write_case(case, path)` creates parent directories (`parents=True, exist_ok=True`) and writes `dump_case(case).encode("utf-8")` with `write_bytes`. Bytes, so that no platform newline translation happens.

`load_case(path)` returns `BenchCase.model_validate(json.loads(path.read_text(encoding="utf-8")))`. Errors are not caught. A pydantic `ValidationError` is a `ValueError`.

`load_cases(directory)` loads every `*.json` under the directory recursively, in sorted path order. If two files carry the same `case_id` it raises `ValueError(f"duplicate case_id {case.case_id}")`. It returns the cases sorted by `case_id`.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| Unknown key anywhere in a case file, including inside a record | `ValidationError`. Every model forbids extra fields. |
| Text with non-ASCII characters, for example a rupee sign | Written as is, not as an escape sequence |
| A file that is not valid JSON | `json.JSONDecodeError` from `load_case`. Not caught. |
| `schema_version` other than 1 | `ValidationError` |
| An amount written as a JSON number in a case file | Accepted by the record models if it has at most two decimals. `dump_case` writes it back as a string with two decimals. Example files use strings. |
| Empty directory passed to `load_cases` | Returns an empty list |
