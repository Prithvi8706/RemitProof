## 1. Objective and rationale

Make retrieval report what it ranked before it applied its four caps, and build from that a `ProofSet`: the capped bundle the model sees (the prompt bundle) plus a second bundle that keeps every ranked invoice and credit (the proof bundle), with a flag that says whether a cap dropped a record that the proof bundle cannot restore.

Why: finding F3. Uniqueness is decided today on a list that was cut to eight invoices (`backend/app/services/candidate_retriever.py:255`). The cut is silent. Later tasks (RP-102 to RP-104) move the uniqueness decision onto the proof bundle. This task only builds the structure. Nothing consumes it yet, so no decision changes.

This implements DD-03 (the prompt bundle never changes) and DD-04 (the proof set is a superset of the prompt view).

## 6. Input and output contracts

### 6.1 `retrieve_with_trace`

Returns `(bundle, trace)`.

- `bundle` is exactly what `retrieve_candidates` returns today for the same arguments.
- `trace.ranked_invoices`: the full sorted invoice list before the `[:8]` slice, as a tuple.
- `trace.ranked_credits`: the full sorted credit list before the `[:3]` slice, as a tuple.
- `trace.dropped_email_ids`: the `email_id` of every email after position 4 in the sorted email list, in sorted order.
- `trace.dropped_strong_customer_ids`: the `customer_id` of every customer after position 3 in the sorted customer list for which at least one of the three strong signals fired, in sorted-list order.

### 6.2 `retrieve_candidates`

Returns `retrieve_with_trace(payment, dataset)[0]`. Keep the existing docstring on this function.

### 6.3 `build_proof_set`

Let `(prompt_bundle, trace) = retrieve_with_trace(payment, dataset)`.

- `proof_bundle.payment`, `proof_bundle.candidate_customers` and `proof_bundle.candidate_emails` equal those of `prompt_bundle`.
- `proof_bundle.candidate_invoices` = `list(trace.ranked_invoices)`.
- `proof_bundle.candidate_credits` = `list(trace.ranked_credits)` followed by every credit in `dataset.credits` whose `invoice_id` is the ID of a proof invoice and whose `credit_id` is not already in the list, sorted by `credit_id` ascending.
- `incomplete_reasons`: `"email_cap"` if `trace.dropped_email_ids` is non-empty, then `"customer_cap"` if `trace.dropped_strong_customer_ids` is non-empty. This order is fixed.
- `complete` = `incomplete_reasons` is empty.

No exception is caught. The function never reads ground truth.

## 8. Algorithm

```
build_proof_set(payment, dataset):
    prompt_bundle, trace = retrieve_with_trace(payment, dataset)
    invoices = list(trace.ranked_invoices)
    invoice_ids = set of invoice_id in invoices
    credits = list(trace.ranked_credits)
    credit_ids = set of credit_id in credits
    extra = [c for c in dataset.credits
             if c.invoice_id in invoice_ids and c.credit_id not in credit_ids]
    credits += sorted(extra, key=credit_id)
    reasons = []
    if trace.dropped_email_ids: reasons.append("email_cap")
    if trace.dropped_strong_customer_ids: reasons.append("customer_cap")
    proof_bundle = CandidateBundle(payment, prompt customers, invoices, credits, prompt emails)
    return ProofSet(prompt_bundle, proof_bundle, not reasons, tuple(reasons))
```

Cost: linear in the dataset size, same order as retrieval.

Why an invoice cap needs no reason: every dropped invoice is in the proof bundle, so nothing is lost. Why an email or strong-customer cap does: a dropped email could carry an instruction or a contradiction, and a dropped strong customer could own a competing allocation. The proof bundle cannot restore either, because customer scores depend on the candidate emails and invoice scores depend on the candidate customers.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| No record exceeds any cap | `proof_bundle == prompt_bundle` in content, `complete` is true, reasons empty |
| A dropped customer has only weak signals (token overlap or an amount match) | Not listed in `dropped_strong_customer_ids`. `complete` stays true. Its invoices with score 100 or more are still in `ranked_invoices`. |
| A credit is linked to a proof invoice but scored below 100 | Appended to the proof credits |
| A credit in `dataset.credits` is already in `ranked_credits` | Not duplicated |
| Empty dataset lists | Empty tuples, `complete` true |
