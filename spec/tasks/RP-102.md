## 1. Objective and rationale

Add one function, `search(proof_set)`, that returns the financially valid allocations together with a status that says how far the answer can be trusted: `unique`, `ambiguous`, `none` or `unknown`.

Why: today three callers read uniqueness from the length of a list (`backend/app/services/baseline_matcher.py:85`, and two places in `backend/app/services/evidence_sufficiency.py`). A list cannot say "I did not look everywhere". `unknown` is the fourth answer that makes an incomplete search visible (DD-05). The enumerator is exponential in the number of invoices per customer, so `search` refuses above 16 (DD-06). It also refuses above three eligible credits per customer, because the enumerator never tries more than three credits together (`backend/app/services/alternative_finder.py:66`) and would silently miss a four-credit allocation.

Nothing consumes `search` in this task. No decision changes.

## 3. Current behaviour and references

`find_valid_alternatives` (`backend/app/services/alternative_finder.py:29`) filters the bundle's invoices into `open_invoices` (`:41` to `:49`) and its credits into `valid_credits` (`:50` to `:57`), then enumerates per customer. Credit subsets are limited to size three (`:66`). The result is sorted and numbered `ALT_001`, `ALT_002` and so on (`backend/app/services/alternative_finder.py:113` closes that expression).

The two filters are inline list comprehensions. `search` needs the same filters to count eligible records before it enumerates. Copying them would let the two drift, so this task turns each into a public function that both use.

## 6. Input and output contracts

### 6.1 `eligible_invoices`

Returns, in bundle order, the invoices of `bundle.candidate_invoices` that satisfy all five conditions of the existing comprehension at `backend/app/services/alternative_finder.py:41`: status is `"open"`, `allocated_payment_id` is `None`, currency equals the payment currency, `issue_date <= payment.date`, and `is_valid_monetary_amount(invoice.amount)`.

### 6.2 `eligible_credits`

Returns, in bundle order, the credits of `bundle.candidate_credits` that satisfy all four conditions of the existing comprehension at `backend/app/services/alternative_finder.py:50`: status is `"valid"`, `consumed_by_payment_id` is `None`, currency equals the payment currency, and `is_valid_monetary_amount(credit.amount)`.

Both functions move the existing conditions. They add none and drop none.

### 6.3 `search`

Evaluated in this order. The first matching row decides.

| # | Condition | `status` | `complete` | `alternatives` | `detail` | `incomplete_reasons` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `proof_set.complete` is false | `unknown` | `False` | `()` | `retrieval_incomplete` | `proof_set.incomplete_reasons` |
| 2 | Some customer has more than 16 eligible invoices in the proof bundle | `unknown` | `False` | `()` | `invoice_limit` | `()` |
| 3 | Some customer has more than 3 eligible credits in the proof bundle | `unknown` | `False` | `()` | `credit_limit` | `()` |
| 4 | Enumeration returns no allocation | `none` | `True` | `()` | `None` | `()` |
| 5 | Enumeration returns exactly one | `unique` | `True` | that one | `None` | `()` |
| 6 | Enumeration returns two or more | `ambiguous` | `True` | all, in enumerator order | `None` | `()` |

Rows 1 to 3 must not call `find_valid_alternatives`. Rows 4 to 6 call `find_valid_alternatives(proof_set.proof_bundle)` exactly once.

"Per customer" means grouped by the record's own `customer_id`, whether or not that customer is a candidate customer.

3. Create `search.py` per 5.2 and 6.3.
4. Create the tests in section 12.

## 8. Algorithm

```
search(proof_set):
    if not proof_set.complete:
        return unknown("retrieval_incomplete", proof_set.incomplete_reasons)
    bundle = proof_set.proof_bundle
    if max count of eligible_invoices(bundle) per customer_id > 16:
        return unknown("invoice_limit")
    if max count of eligible_credits(bundle) per customer_id > 3:
        return unknown("credit_limit")
    alternatives = tuple(find_valid_alternatives(bundle))
    status = "none" if len == 0, "unique" if len == 1, else "ambiguous"
    return SearchOutcome(status, True, alternatives, None, ())
```

Cost: the enumerator visits at most 2^16 invoice subsets times 8 credit subsets per customer. Measured in the audit: 597 ms at 16 invoices.
