## 1. Objective and rationale

Add a baseline that decides a payment with the existing deterministic checks and no model. For every financially valid allocation it asks the unchanged proof engine and sufficiency gate whether that allocation would be authorized, and it resolves only when exactly one would.

Why: it is the measurement that shows what the model contributes (finding F1), and it is the detector for finding F4, where more than one allocation is authorizable. It implements DD-10 and is the first form of the rule in DD-09.

This module is an evaluation baseline. Nothing in the running application may import it in this task.

## 6. Input and output contracts

**`canonical_proposal(bundle, alternative)`** returns an `InvestigationProposal` with:

| Field | Value |
| --- | --- |
| `payment_id` | `bundle.payment.payment_id` |
| `proposed_customer` | `alternative.customer_id` |
| `invoice_ids` | `list(alternative.invoice_ids)` |
| `credit_ids` | `list(alternative.credit_ids)` |
| `evidence_ids` | In this order, duplicates removed keeping the first occurrence: `alternative.customer_id`; then `sorted(alternative.credit_ids)`; then the `email_id` of each email in `bundle.candidate_emails`, in bundle order, whose `customer_id == alternative.customer_id` |
| `semantic_claims`, `unresolved_questions` | Left at defaults (empty lists) |

Invoice IDs are not cited. They are already the proposal's `invoice_ids`.

**`verifier_only_decision(bundle)`** returns a `VerifierOnlyOutcome`:

| Situation | `decision` | `reason` | `proposal` |
| --- | --- | --- | --- |
| Exactly one alternative is authorizable | `"resolve"` | `REASON_UNIQUE` | Its canonical proposal |
| There are no alternatives | `"abstain"` | `REASON_NO_ALLOCATION` | `None` |
| There are alternatives and none is authorizable | `"abstain"` | `REASON_NONE_AUTHORIZABLE` | `None` |
| Two or more are authorizable | `"abstain"` | `REASON_MULTIPLE_AUTHORIZABLE` | `None` |

Evaluate the rows in that order. `alternatives_considered` is the number of alternatives. `authorizable_allocation_ids` is the tuple of `allocation_id` values of authorizable alternatives, in the order `find_valid_alternatives` returned them. `payment_id` is `bundle.payment.payment_id`.

An alternative is authorizable when `evaluate_evidence_sufficiency(bundle, P, verify_candidate(bundle, P), alternatives).safe_to_resolve` is true, where `P` is its canonical proposal and `alternatives` is the full list from `find_valid_alternatives(bundle)`.

**`VerifierOnlyInvestigator.investigate(bundle)`**: computes `outcome = verifier_only_decision(bundle)`, stores it at `self.outcomes[bundle.payment.payment_id]`, and returns `outcome.proposal` when it is not `None`, otherwise `InvestigationProposal(payment_id=bundle.payment.payment_id)`. It never raises on its own.

## 8. Algorithm

```
canonical_proposal(bundle, alternative):
    email_ids = [e.email_id for e in bundle.candidate_emails
                 if e.customer_id == alternative.customer_id]
    evidence = unique_in_order([alternative.customer_id]
                               + sorted(alternative.credit_ids)
                               + email_ids)                # list(dict.fromkeys(...))
    return InvestigationProposal(payment_id, proposed_customer, invoice_ids, credit_ids, evidence_ids=evidence)

verifier_only_decision(bundle):
    alternatives = find_valid_alternatives(bundle)          # call once
    authorizable = []
    for alternative in alternatives:
        proposal = canonical_proposal(bundle, alternative)
        proof = verify_candidate(bundle, proposal)
        sufficiency = evaluate_evidence_sufficiency(bundle, proposal, proof, alternatives)
        if sufficiency.safe_to_resolve:
            authorizable.append((alternative, proposal))
    choose decision, reason, proposal from the table in section 6
    return VerifierOnlyOutcome(...)
```

Cost: one proof and one sufficiency evaluation per alternative. The bundle holds at most 8 invoices, so the number of alternatives is small.

## 9. Edge cases and error handling

| Case | Required behaviour |
| --- | --- |
| Empty bundle or no invoices | `find_valid_alternatives` returns `[]`; outcome is abstain with `REASON_NO_ALLOCATION` |
| An alternative with credits | Credits are cited, sorted, after the customer |
| Emails of other customers in the bundle | Not cited for this alternative |
| The same email ID could appear twice | Impossible: `CandidateBundle` rejects duplicate IDs. `dict.fromkeys` still guarantees uniqueness. |
| An exception from the proof engine or the gate | Do not catch it. Let it propagate. |
| Input bundle | Never mutated |

No `try`, no logging, no caching, no randomness, no I/O in this module.
